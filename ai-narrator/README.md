# AI Narrator — upstream-first extension

Status: **experimental implementation; not production verified** (2026-11-18). Branch: `feature/ai-narrator`. No automated merge/release.

## Architecture and integration boundary

- `ai-narrator/src/main/kotlin/.../NarratorCore.kt`: independent line/frame models, style rules, cache identity, pricing and scheduling policy. No Nuvio, ExoPlayer or mpv dependencies.
- `NarratorOverlay.kt`: **sole Nuvio adapter**; observes existing `PlayerRuntimeController.uiState`, `playbackTimeline`, `subtitleCueTracker.state`, and mpv's public `sub-text` property. Converts each to immutable narrator contracts.
- `NarratorEngine.kt`: asynchronous prefetch (two requests in parallel), seek/discontinuity reset, late-cue suppression, independent audio output via Android `MediaPlayer`, no modifications to ExoPlayer/mpv.
- `GeminiNarratorTts.kt`: Gemini API REST transport; `speechMetadata.style` per utterance; default WAV, bounded response and disk cache.
- `NarratorPreferences.kt`: Android Keystore-encrypted user API key, local monthly *estimated* cost reservation.
- Existing fork-owned `app/reshaped.gradle`: includes new source/test source sets.
- One integration call in upstream `PlayerScreen.kt`, near the other overlays. No controller internals modified.

## Important functional limitations

1. The present adapter offers **best-effort** narration from currently visible text. The optional existing `subtitleAutoSyncCues` timeline is trusted only after a visible-text match. Other subtitles have no reliable lookahead timing through the current contract. Short cues are **skipped rather than spoken too late**. Full multi-minute prefetch requires a stable timed-cue feed for the selected subtitle source.
2. Separate Android audio stream mixes at system mixer only where hardware routes allow it. Dolby/DTS bitstream passthrough and exclusive audio may not mix; original-track attenuation is not implemented. No modification to the original audio decoder.
3. The conservative budget uses estimated tokens, *not* verified API usage and is per device. It is **not a hard billing ceiling**, particularly for retries, billing adjustments or other devices.
4. No live API credentials, listening tests, audio hardware, Gradle compilation or upstream dry merge were available in this execution environment. Treat functionality as unverified until all acceptance checks succeed.
5. The client-side encrypted API key is kept on the user's device but requests go directly to Gemini. For production deployments prefer a secured, quota-enforcing backend; never distribute shared API keys inside an APK.
6. Synthesis currently requires default WAV output and a working `gemini-3.8-*-tts` model on the configured Gemini Developer API account. Google Cloud Enterprise endpoints use OAuth and require a distinct transport.

## Configuration and behavior

Open playback controls, then **Lektor AI**. Enter an individual Gemini API key, choose Flash/Flash-Lite, enable, select voice level and estimated monthly limit. Changes are saved on demand. The feature starts disabled. The on-device cache has a 96 MiB maximum. If narration cannot be synthesized before the subtitle's end, narration is not started.

Default voice: `Kore`. Natural, neutral Polish style, with restrained question/exclamation phrasing. It never intentionally adds dialog beyond the subtitle itself. The two specified Gemini IDs and per-turn speech metadata are documented at:
- https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/text-to-speech/overview
- https://cloud.google.com/model-garden/pricing

## Maintenance guide (no merge to main)

1. Use a clean, separate checkout/worktree and make sure `main`, `subtitle-autosync` and other contributors' worktrees are not modified. Never force-push shared branches.
2. Fetch the existing official upstream tag in the **existing** AutoSync process. Do not replace `.github/workflows/mirror-nuviotv-release.yml`.
3. In `Actions > AI narrator compatibility`, select `feature/ai-narrator` and optionally specify the exact official Nuvio tag to test. The workflow uses an isolated **detached Git worktree**, runs a noncommitting merge and produces a conflict report.
4. Require passing `:app:compileFullDebugKotlin`, `:app:testFullDebugUnitTest`, and contract checks. Also run manual playback tests for ExoPlayer and mpv: start, pause, resume, seek, switching streams, subtitles on/off, network failure, buffering, passthrough/mixed PCM.
5. If a conflict occurs, inspect the exact path and diff. Preserve only the tagged one-line narrator hook in `PlayerScreen.kt`; never copy whole upstream classes or blindly select ours/theirs.
6. Compare the integration report against the original branch. If a source changes a tracked contract, update **only** `NarratorOverlay.kt` and its contract test.
7. Test against other source forks only after defining their exact repository/ref and ensuring common ancestry. The current repository documentation mentions Echo logic cherry-picks but does not define a stable automatic merge route for Echo/Reshaped.
8. Do not publish releases, create automatic merges into `main`, or enable narrator by default. Review the compatibility report and listening results before any manual integration.

## ZONOS3-Mini: on-device, offline pre-render (updated 2026-11-18)

The previously described LAN-hosted ZONOS3 mode is **retired**. The ZONOS3 choice now means inference executed directly on Android TV, via a private loopback subprocess, never a computer on the local network. Inference is intentionally **disabled while playback is running**: the player reads only pre-generated WAVs.

- **User-triggered model acquisition**: ZonosOnDeviceModels downloads the two pinned, SHA-256-verified GGUF files (~1.12 GB) into Android private persistent storage. Partial downloads can resume, and deletion is explicit.
- **Offline first/second-half preparation**: NarratorPreparationPlan validates that the subtitle timeline covers the film; NarratorPreparer processes one cue at a time while playback is paused, shows progress, stops after a 15-minute session and retains all successfully generated WAVs. More sessions may be necessary.
- **Permanent audio reuse**: NarratorPersistentAudio keeps already-made WAVs in filesDir, not cacheDir. No silent eviction; a 2 GiB audio limit and 500 MiB free-space reserve prevent unbounded growth.
- **2/3/4 GB memory guard**: ZonosMemoryGuard uses actual available system memory, low-memory signals and process metrics before and during inference. A 2 GB Android TV device may be refused if insufficient free RAM; operating a 1.12 GB model on that class is not proven safe.
- **Missing native dependency**: ZonosNativeServer requires a tested Android ARM64 PIE binary packaged as libzonos3_server.so in the APK native library directory. The repository adds an experimental NDK build script but **does not contain a built or validated native binary**. Therefore end-to-end ZONOS3 speech generation is currently BLOCKED, not implemented-and-verified.

See [ZONOS3_LOCAL.md](ZONOS3_LOCAL.md) for architecture, UI, memory thresholds, native build blocker and acceptance tests. A complete timed subtitle track must be exposed by Nuvio for first/second-half preparation; subtitleAutoSyncCues alone may not contain it for normal tracks. There is no translation engine: spoken language depends on preexisting Polish subtitles.

No successful Gradle build, native ARM64 execution or real-device memory/performance tests are available. Do not claim a 15-minute full-half completion or 2 GB compatibility until benchmarked.
